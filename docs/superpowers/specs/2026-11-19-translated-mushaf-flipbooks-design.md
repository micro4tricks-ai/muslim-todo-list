# مصاحف مترجمة بقلب صفحات حقيقي — وثيقة التصميم والتسليم

التاريخ: 2026-11-19 — الحالة: **مسودة تنتظر موافقة المالك** (لم يُكتب أي كود).
هذا الملف مكتوب ليكمل منه أي جهاز/جلسة Claude Code من غير سياق المحادثة.

## الفكرة والسبب
المالك رأى في موقع alsaifgallery.com/SA_ar/magazine مجلة تُقلَّب صفحاتها بثني حقيقي
كالورق، وأعجبه ذلك. يريد نفس التجربة لمجموعة **حوالي 60 مصحفاً مترجماً** (PDF سكان
بدقة عالية، على فلاشة في البيت) داخل تطبيق «مهام المسلم / Muslim Activity» للأندرويد.

ما تبيّن من الموقع: التأثير خدمة تجارية (FlipHTML5) مضمّنة، وكل صفحة صورة WebP.
أي أن الطريقة هي PDF ← صور ← عارض قلب. لا ننسخ كود تلك الخدمة.

## الأهداف
- 60 مصحفاً في قسم «كتب/مصاحف مترجمة» داخل المكتبة الحالية.
- قلب صفحات حقيقي (ثني) بالسحب على الموبايل، وصفحتان متقابلتان على الشاشة العريضة.
- شريط تقدم + عدّاد صفحات (مثل 1/23) + أزرار أول/آخر/تالي/سابق.
- القراءة بدون نت بعد «تنزيل» الكتاب.

## غير الأهداف / ما يفشل التصميم
- لا نضمّن الكتب في الـAPK (≈ 3 جيجا تقديراً).
- لا نستخدم كود FlipHTML5 ولا أي خدمة مدفوعة.
- لا نخرّب قارئ المصحف الحالي (`mushaf-book.js`) ولا نغيّر appId أو مفاتيح التوقيع.
- لا يتعطل التطبيق لو الجهاز بلا نت: القائمة والأغلفة المخزّنة تظهر.

## القيود
- اللابتوب بلا كرت شاشة ← الأداة **CPU فقط** (لا CUDA ولا نماذج AI).
- الحجم كبير: الأداة تعمل على دفعات وتكمل من حيث وقفت.
- حقوق النشر: مصاحف مترجمة سكان من ناشرين مختلفين. قبل أي نشر عام في المتجر أو رفع
  على موقع عام، **المالك يتأكد** أنه مسموح له. للاستخدام الشخصي لا مشكلة.

## الطرق التي نُظر فيها
- **أ) صور + StPageFlip (المختارة كترشيح، تنتظر تأكيد المالك):** تحويل مسبق لصور WebP
  وعارض قلب مفتوح المصدر (MIT). سريع، يعمل على الموبايل، يعمل بلا نت. العيب: النص
  صورة (لا نسخ ولا بحث)، والحجم كبير فيُستضاف خارج الـAPK.
- ب) عرض PDF مباشرة بـpdf.js + عارض القلب: بلا تحويل لكنه ثقيل ويتقطع مع الملفات
  الكبيرة على الموبايلات الضعيفة. مرفوض لحجم السكانات.
- ج) توسيع قلب CSS الحالي للموبايل: قلب ورقة جامدة لا ثني حقيقي، لا يطابق المطلوب.

## تصميم الأداة (CPU فقط)
أداة بايثون مستقلة (مثلاً `tools/flipbook-convert/convert.py`) بـ PyMuPDF + Pillow:
1. تقرأ مجلداً فيه الـPDFs.
2. لكل كتاب: تصيّر كل صفحة بعرض هدف (ابدأ بـ 1200px) وتحفظها WebP جودة ~75،
   في `out/<book-id>/p001.webp ...` + `cover.webp` (صغير) + `book.json`
   (الاسم، اللغة إن عُرفت، عدد الصفحات، نسبة العرض/الارتفاع).
3. فهرس واحد `out/index.json` لكل الكتب.
4. تكمل من حيث وقفت (تتخطى الكتاب المكتمل، ملف علامة `.done`).
5. تعمل بالتوازي بعدد أنوية الجهاز، وتطبع تقدماً وحجماً إجمالياً.
6. تطبع تقدير الحجم النهائي بعد أول كتاب.
اختبر أولاً على **كتاب واحد** وقِس حجم الصفحة قبل تشغيل الـ60.
تتفادى معرفات الكتب الأحرف العربية (استخدم رقماً/ترجمة لاتينية).

## جانب التطبيق
- قائمة الكتب من `index.json` بالأغلفة.
- فتح كتاب: StPageFlip (نسخة محلية داخل المشروع، ترخيص MIT يُذكر)، تحميل الصفحات
  كسولاً (الحالية + المجاورة فقط).
- زر «تنزيل للقراءة بدون نت»: يخزّن الصفحات (Cache API / ملفات) ويظهر الحجم قبل التنزيل.
- الاستضافة: تُحدَّد بعد قياس الحجم الحقيقي (ترشيح: استضافة Hostinger للمالك أو
  GitHub Pages لو الحجم يسمح). الـAPK يحمل القائمة والأغلفة فقط.
- احترام `prefers-reduced-motion` / وضع `data-calm` كما يفعل `mushaf-book.js`.
